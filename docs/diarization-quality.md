# Full diarization evaluation (C1)

`tools/benchmark_diarization.py` evaluates **raw speaker activity** in `diar/diarization.json` against
independent RTTM annotations. It runs only `convert → diarize`; ASR omissions, alignment and merge's
single-speaker segments cannot hide overlapping speakers. It uses the already installed, pinned
`pyannote.metrics 3.2.1` and `pyannote.core 5.0.0`; no runtime dependency or product cache version changes.

## Metric contract

DER is `(false alarm + missed speech + speaker confusion) / reference speaker duration`. All four
durations are in **speaker-seconds**: two speakers active for one second contribute two seconds to the
denominator. Labels are matched one-to-one using the Hungarian algorithm. See the
[official pyannote.metrics definition](https://pyannote.github.io/pyannote-metrics/reference.html#diarization).
Extra simultaneous hypothesis speakers also count as false alarms when reference speech is present.

The default protocol is **collar 0, overlap included**, over an explicit UEM (evaluated time regions).
Unlabelled intervals inside UEM count as non-speech, so predicted speech there is a false alarm. Nothing
outside UEM is scored. UEM is required; the scorer never estimates it from reference/hypothesis extents.
`--collar 0.5` removes a total 0.5-second region around each reference boundary, **0.25 seconds on each
side**, using pyannote's convention. `--skip-overlap` is an explicit diagnostic alternative; it is never
enabled implicitly. Both exclusions are applied before choosing the global speaker mapping, once only.

The report contains total, overlap and non-overlap error components. The latter two reuse the **same
recording-wide mapping** and add up to the total; locally remapping just the overlap would hide mistakes.
`evaluated_seconds` is wall-clock duration, while `reference_speaker_seconds` counts simultaneous speakers
separately. `reference_overlap_seconds_before_exclusions` exposes the amount of original overlap even
when it is excluded by a diagnostic policy. No speech in a scored region means `der: null`, with false
alarms still reported; this is not assigned a misleading perfect score. DER can exceed 100%.

Corpus DER sums error components and divides by summed reference speaker-seconds, rather than averaging
per-file percentages. Different scoring policies/scorer versions cannot be aggregated. Failed cases remain
in the report, `coverage` lists planned/completed/failed counts, and any failure gives exit code 1. A partial
corpus's aggregate must not be presented as a complete-corpus score. There is no automatic accuracy gate.

Reference/hypothesis readers accept single-recording, channel-1 RTTM `SPEAKER` rows; the hypothesis may
instead be raw Diarrhizer JSON with `stage: diarize` and `speaker` labels. Exported/merged words are rejected.
Empty RTTM is valid for a silent reference/hypothesis; UEM must be nonempty. Duplicate and intersecting
intervals for the same speaker are unioned, including contiguous segments, so they cannot inflate overlap
or add artificial collar boundaries. Different speakers at identical times remain distinct tracks.
Malformed, non-finite, negative or reversed intervals, missing labels and wrong recording/channel IDs
are errors. For multi-recording RTTM, split into one file per recording before building a manifest.

## Annotated human-speech corpus

The pinned mini-corpus uses the **first three alphabetically sorted dev recording IDs** in
[VoxConverse v0.3](https://github.com/joonson/voxconverse), selected before inference. The complete
recordings total **883.9179375 seconds** (14 min 44 s), including **59 seconds of reference overlap**.
This is a small reproducible development subset, not the full VoxConverse benchmark or an unseen test set.

The overlap contains **121.60 reference speaker-seconds**, including **3.60 seconds of three-speaker activity**.
RTTM files are unmodified upstream annotations pinned to commit
`24bf60be297701cd7e4ef18550c6d390c1b87365`; hashes, durations, source and
[attribution/license](../tools/fixtures/voxconverse-dev-mini/README.md) accompany them. Data references
retain CC-BY-4.0 independently of the project's MIT code. Audio is neither committed nor redistributed
with this repository. Generated UEM covers each complete recording from 0 to the exact WAV duration.
Reference activity is not generated by the diarization model, an energy threshold or the TTS envelope.

## Reproduce

Run with the supported product environment from [development.md](development.md). Download/preparation
needs no Hugging Face token. `--download` retrieves only the selected WAV members of the official public
ZIP using bounded HTTP ranges (about 28 MB uncompressed), verifies CRC/size and pinned SHA-256, and
refuses a server response that would download the whole archive. Existing matching audio is reused.

```powershell
python tools/prepare_der_corpus.py --download --out "$env:TEMP\diarrhizer-der-corpus"
# Alternatively use the WAV directory of an already downloaded/extracted official dev archive:
python tools/prepare_der_corpus.py --audio-dir "D:\datasets\voxconverse\audio" --out "$env:TEMP\diarrhizer-der-corpus"

# Set HF_TOKEN/HUGGINGFACE_HUB_TOKEN locally; never paste it into a command saved in Git.
# Offline flags require the diarization models to be cached already.
$env:HF_HUB_OFFLINE = '1'
$env:TRANSFORMERS_OFFLINE = '1'
python tools/benchmark_diarization.py "$env:TEMP\diarrhizer-der-corpus\corpus.json" --out "$env:TEMP\der-cuda-jobs" --report "$env:TEMP\der-cuda.json" --device cuda
python tools/benchmark_diarization.py "$env:TEMP\diarrhizer-der-corpus\corpus.json" --out "$env:TEMP\der-cpu-jobs" --report "$env:TEMP\der-cpu.json" --device cpu
```

Model execution loads locally configured HF credentials and creates a fresh job per recording. Defaults
are `--min-speakers 1 --max-speakers 10`, **without supplying the reference speaker count**. Bounds,
device, raw audio preprocessing, scoring policy, scorer/package versions and audio/reference/UEM/hypothesis
hashes are recorded. `--only ahnss` selects recordings; `--repeat 3` repeats the chosen subset. Model cache
and OS cache can stay warm; wall time includes conversion and model loading, not just steady inference.
`std(): degrees of freedom` warnings from pyannote remain visible and are not evidence of a passing score.

Score an existing hypothesis, change collar or compare overlap exclusion without rerunning models:

```powershell
python tools/diarization_metrics.py --uri ahnss --reference "$env:TEMP\diarrhizer-der-corpus\ahnss.rttm" --uem "$env:TEMP\diarrhizer-der-corpus\ahnss.uem" --hypothesis "out\<job>\diar\diarization.json" --report "$env:TEMP\ahnss-der.json"
# Append --skip-overlap for a separate diagnostic, or --collar 0.5 for ±250 ms tolerance.
```

Standalone reports include input hashes. Changing reference/coverage/audio invalidates the suite's
manifest verification before any model is loaded. The suite verifies WAV duration and checks that reference
and UEM stay within it. Keep generated corpus copies, hypotheses and reports outside Git.

## Using another annotated corpus

Use one recording per case, relative paths inside the manifest directory, original-time annotations,
and a UEM that explicitly distinguishes unannotated time from annotated silence. The manifest shape is:

```json
{
  "schema_version": 1,
  "task": "speaker_diarization",
  "cases": [{
    "id": "recording_01",
    "audio": "recording_01.wav", "audio_sha256": "<SHA-256 of WAV bytes>",
    "reference": "recording_01.rttm", "reference_sha256": "<SHA-256 of RTTM bytes>",
    "uem": "recording_01.uem", "uem_sha256": "<SHA-256 of UEM bytes>",
    "duration_seconds": 30.0
  }]
}
```

RTTM example: `SPEAKER recording_01 1 2.0 3.0 <NA> <NA> speaker_A <NA> <NA>` means speaker A is
active from 2 to 5 seconds. Another speaker's intersecting row is retained as overlap. UEM example:
`recording_01 1 0 30`. The synthetic ASR corpus's utterance envelopes are deliberately not accepted as
reference RTTM: they include silence and are not independent acoustic annotations.

## Measured baseline, 2026-11-04

Windows 10 build 19045, Ryzen 7 5700X, RTX 3090, Python 3.12.13, WhisperX 3.3.1 / pyannote.audio 3.3.2,
default `pyannote/speaker-diarization-3.1`, pyannote.metrics 3.2.1, pyannote.core 5.0.0. CUDA uses
torch 2.3.1+cu121; CPU uses torch 2.3.1+cpu. The model/thresholds were not tuned on these recordings; revisions of downloaded
diarization weights are still not captured, so package versions alone cannot guarantee identical weights.

Strict results (collar 0, overlap included, speaker bounds 1–10); CPU and CUDA produced the same
error components for all three recordings:

| Recording | False alarm, s | Missed speech, s | Confusion, s | Reference speaker-s | DER |
| --- | ---: | ---: | ---: | ---: | ---: |
| abjxc | 0.3775 | 0 | 0 | 62.60 | 0.6030% |
| afjiv | 11.5190 | 0.4965 | 0.3353 | 123.64 | 9.9894% |
| ahnss | 12.5123 | 17.2956 | 12.3187 | 723.08 | 5.8260% |
| Aggregate | 24.4088 | 17.7921 | 12.6540 | 909.32 | **6.0325%** |

Overlap breakdown with the same global mapping: missed speech **14.5977 s**, confusion **8.2285 s**,
false alarm **0 s**, denominator **121.60 speaker-s**, DER **18.7715%**. Non-overlap DER is **4.0660%**.
The sum of the two sets of error components is the full-corpus numerator. Re-scoring the same hypotheses
with overlap excluded gives 4.0660%; with collar 0.5 and overlap included it gives 2.1652%. These are
**different evaluation policies**, not improvements to the model.

All six CPU/CUDA jobs completed. CUDA wall time totaled 21.744 s including model loading. This short, ordered
run is not a throughput benchmark. The largest remaining errors are missed/incorrect speakers in overlap
and false alarms outside it. Next steps are a larger held-out corpus in relevant call languages/domains,
confidence intervals and fixed acceptance thresholds; full RAM/VRAM measurement also remains open.
